Dotboard privacy policy

Last updated 11 November 2026

In short: Dotboard has no accounts, ads, analytics or tracking, and it doesn't access your location. To show departures it sends only the station code you chose. Your settings stay on your phone.

This policy covers the Dotboard app for Android (package io.github.inputbiscuit.dotboard), however you install it, and the small proxy server it uses to fetch departures. Dotboard is an independent, open-source project; you can read all of its code at github.com/InputBiscuit/dotboard.

What Dotboard doesn't do

  • No accounts or sign-in.
  • No ads, analytics, crash reporting or tracking of any kind, and no third-party SDKs that collect data.
  • No access to your location, contacts, photos, files, camera or microphone.
  • No selling or sharing of personal data.

Fetching departures

To show a board, Dotboard asks for departures from a station. How that request travels depends on your settings.

By default, through Dotboard's proxy. The app sends a request to Dotboard's proxy, a small server run on Cloudflare Workers. The request contains:

  • the three-letter code of the station you chose (for example PAD for London Paddington), and
  • the code of a "calling at" station, if you set one.

Like any server, the proxy also sees your IP address. It uses the IP address only for a moment, to limit how many requests one device can make so the service can't be abused. The proxy keeps no logs and stores neither your IP address nor your requests. It then asks the Rail Data Marketplace for that station's departures, using Dotboard's own key, and passes the result back. The Rail Data Marketplace sees the request as coming from Cloudflare, not from you.

Departure boards are public timetable information. The proxy keeps a copy of each board for about 45 seconds, so that people watching the same station share one request. These copies contain no information about you.

Cloudflare runs the infrastructure the proxy is hosted on and handles traffic under its own privacy policy.

With your own API key. If you enter your own Rail Data Marketplace key in Settings, the app skips the proxy and talks to the Rail Data Marketplace (raildata.org.uk) directly. It sends the station code, the optional "calling at" code and your key. The Rail Data Marketplace also sees your IP address, and handles it under its own terms, which you accepted when you signed up for the key.

Sample data. With "Use sample data" turned on, the app shows built-in sample boards and doesn't connect to anything.

All connections use HTTPS, so they're encrypted in transit.

What's stored on your phone

  • Your settings: default station, board colours, clock format, refresh interval and sample-data choice.
  • Each widget's station and optional "calling at" station.
  • Your own API key, if you entered one, encrypted with a key held in Android's secure keystore. It's never logged and only ever sent to the Rail Data Marketplace.
  • Recently fetched departure boards, so a widget can keep showing the last board when there's no connection.

None of this leaves your phone, and Dotboard turns off Android's cloud backup, so it isn't copied to your Google account either. Uninstalling Dotboard, or clearing its storage in Android's settings, deletes all of it.

Links

A few buttons in the app open web pages in your browser, such as the Rail Data Marketplace's sign-up page and Dotboard's source code on GitHub. Those websites have their own privacy policies.

App stores

If you install Dotboard from Google Play or another store, that store handles your download and any information it collects under its own privacy policy. Dotboard receives nothing about you from it.

Children

Dotboard isn't aimed at children and doesn't knowingly collect any information from anyone, including children.

Changes to this policy

If Dotboard's handling of data changes, this page will be updated before the new version is released, and the date at the top will change. The page's full history is public in the project's repository.

Contact
